# Infrastructure Cost Optimization

How Health Watchers keeps cloud spend efficient without compromising the SLOs or
the DR posture. Targets are enforced through automated reports, budgets, and a
monthly review.

| Attribute | Value |
|-----------|-------|
| Target | ≥ 20% reduction in monthly run-rate vs the pre-programme baseline |
| Utilization target | ≥ 80% average CPU/memory on stateful node pools |
| Budget policy | Hard alerts at 80% / 100% / 120% of monthly budget; auto-throttle non-prod at 100% |
| Reporting | Automated weekly (`cost-report` workflow) + monthly review |
| Owner | Platform Engineering + Finance partner |

## 1. Baseline and targets

The baseline is the average of the three full calendar months before the
programme start, by service and by environment, recorded in
`ops/cost/baseline.json` (generated by `scripts/cost/cost-report.sh --set-baseline`).
Every weekly report shows current run-rate vs baseline and vs the 20% goal.

| Lever | Expected saving | Owner |
|-------|-----------------|-------|
| Right-sizing over-provisioned workloads | 8–12% | Platform |
| Spot for stateless + batch | 5–8% | Platform |
| Savings Plans / RIs for the steady-state floor | 6–10% | Platform + Finance |
| Storage tiering + orphan cleanup | 2–4% | Platform |
| Cross-region / egress reduction (CDN, same-AZ) | 2–3% | Platform |

## 2. Resource utilization analysis

`scripts/cost/analyze-utilization.sh` — run weekly, also in the `cost-report`
workflow.

- Kubernetes: `kubectl top` + Prometheus `container_cpu_usage_seconds_total` /
  `container_memory_working_set_bytes` vs requests/limits, per workload, p50/p95
  over 14 days.
- Nodes: average allocatable vs used; flags pools below the 80% target.
- EC2 / RDS (outside k8s): CloudWatch `CPUUtilization`, `NetworkIn/Out`,
  `FreeableMemory` p95 over 14 days.
- Output: a table + `hw_cost_utilization_ratio{scope=...}` metrics + JSON.

## 3. Right-sizing

`scripts/cost/rightsizing-recommendations.sh` produces concrete change
recommendations (no automatic mutation):

- Per workload: recommended CPU/memory requests = p95 usage × 1.2, rounded to a
  sane step; shows current vs recommended and the monthly $ delta.
- Per node pool: recommended instance family/size and count.
- Consumes AWS Compute Optimizer findings when available.
- Emits a Markdown block for the PR description and a CSV for Finance.

Apply via a normal PR to `helm/health-watchers/values-*.yaml` or the k8s
manifests; the monthly review triages the backlog.

## 4. Reserved capacity and Spot

- **Steady-state floor** (measured as the 30-day p5 of total compute) is covered
  by 1-year no-upfront Compute Savings Plans / RIs. Target coverage 70–85% of the
  floor — never 100%, to stay flexible. Plan and coverage tracking:
  [`ops/cost/reserved-capacity-plan.md`](../ops/cost/reserved-capacity-plan.md).
- **Spot** for everything that tolerates interruption: web, API (with a
  guaranteed on-demand minimum), async workers, CI runners, and the DR
  warm-standby. Config: [`ops/cost/karpenter-nodepool-spot.yaml`](../ops/cost/karpenter-nodepool-spot.yaml)
  — 70% spot / 30% on-demand for `api`, 100% spot for workers, consolidation on.
- Stateful (MongoDB, Redis, Vault) stays on-demand / reserved only.

## 5. Storage optimization

- S3: lifecycle rules — backups `STANDARD_IA` after 0 days, `GLACIER_IR` after
  35, expire per retention; uploads `INTELLIGENT_TIERING`; incomplete multipart
  uploads aborted after 7 days.
- EBS: `gp3` everywhere (cheaper than `gp2` at equal perf); right-size volumes
  under 40% used; delete-on-terminate for ephemeral.
- Snapshots: keep N per volume, delete the rest (see cleanup script).
- MongoDB: TTL indexes on `audit_logs`, `sessions`, soft-deleted docs; archive
  cold collections to compressed S3.

## 6. Unused resource cleanup

`scripts/cost/cleanup-unused-resources.sh` — **dry-run by default**, `--apply` to
act, always writes a report and skips anything tagged `keep=true` or younger than
`--min-age-days` (default 7).

Targets: unattached EBS volumes, unassociated Elastic IPs, orphaned snapshots
(no source volume / beyond retention), idle load balancers (0 healthy targets
14 d), unused security groups & target groups, stale ECR/registry images
(untagged or beyond the last N), stopped EC2 instances older than 30 d,
empty/idle non-prod namespaces.

## 7. Cross-region / egress

- Serve static assets and API cache from the CDN (see
  [`CDN_CACHING_STRATEGY.md`](./CDN_CACHING_STRATEGY.md)) — cuts origin egress
  ~30%.
- Keep chatty services in the same AZ (topology-aware routing) to avoid
  cross-AZ data charges.
- DR replication uses S3 CRR (cheaper than re-uploading) and compresses before
  transfer.
- VPC endpoints for S3 / ECR / Secrets Manager to avoid NAT egress cost.

## 8. Cost allocation and tracking

- Every resource carries: `app`, `env`, `component`, `owner`, `cost-center`.
  Kubernetes: enforced by the labels in
  [`k8s/cost-allocation-labels.yaml`](../k8s/cost-allocation-labels.yaml) + a
  Kyverno/OPA policy that rejects unlabeled workloads.
- AWS: cost-allocation tags activated in Billing; a Cost Categories rule maps
  tags → team.
- `scripts/cost/cost-report.sh` pulls Cost Explorer grouped by tag and service,
  month-over-month, and writes `hw_cost_month_to_date_usd{...}` for Grafana.

## 9. Budgets and controls

- [`ops/cost/budgets.json`](../ops/cost/budgets.json): per-environment monthly
  budgets with alerts at 80 / 100 / 120% to `#cost-alerts` + Finance.
- At 100% of a **non-prod** budget, an automation scales non-prod deployments to
  zero overnight and blocks new expensive resource types until reviewed.
- Prod budget breach pages Platform; no automatic action on prod.
- Alerts also surface in Prometheus via
  [`monitoring/alerts-cost.yml`](../monitoring/alerts-cost.yml).

## 10. Monthly review process

First Wednesday of each month, 45 min, Platform + Finance:

1. Walk the latest `cost-report` output: run-rate vs baseline vs 20% target,
   biggest movers.
2. Triage the right-sizing backlog — accept / defer / reject each item, open PRs.
3. Review Savings Plan / RI coverage and utilization; adjust the plan.
4. Review cleanup report — confirm nothing was wrongly reclaimed; approve next
   `--apply` run.
5. Check every environment is inside budget; adjust budgets with justification.
6. Record decisions and action items in `docs/COST_REVIEW_LOG.md`.

## 11. Acceptance criteria mapping

| Criterion | How it is met |
|-----------|---------------|
| Monthly cost reduced by 20% | Tracked in every `cost-report` vs `ops/cost/baseline.json`; reviewed monthly |
| Utilization > 80% | `analyze-utilization.sh` + `hw_cost_utilization_ratio` alert; right-sizing backlog |
| Budgets enforced | `ops/cost/budgets.json` + non-prod auto-throttle at 100% + Prometheus alerts |
| Cost reporting automated | `cost-report` workflow weekly → artifacts, Slack, Grafana metrics |
