# API validation rules

API handlers should validate request `body`, `params`, and `query` values with Zod via `validateRequest`.

Standard rules:

- ObjectId parameters must be 24-character MongoDB ObjectIds.
- Pagination accepts `page` >= 1, `limit` from 1 to 100, and optional cursor tokens generated by the pagination utility.
- Monetary values must be positive and use at most two decimal places.
- Unknown fields should be rejected with `.strict()` for create/update payloads unless the endpoint explicitly supports partial or extensible data.
- Validation failures return `400` with `error`, `code`, `message`, `details`, and `requestId`.

Reusable schemas live in `src/shared/validation`.
